acptoapi credit-dead exclusion gotcha: a brand's /models catalog endpoint can be billing-blind (returns clean 200 model list) while /chat/completions 402s CreditsError on every model (e.g. opencode-zen) - the catalog probe alone cannot detect this. lib/brand-catalog.js's isCreditDead/markCreditDead/isDead extend the existing isAuthDead (401/403) pattern to 402/credit-dead, fed by both the catalog probe and live chat-request failures via chain-machine.js's markProviderFailed calling markCreditDead on reason==='credit_dead'. refreshAll's per-brand cache write must preserve an existing creditDead/creditDeadAt flag across refresh cycles (merge, never blind-overwrite the cache entry) or the next periodic re-probe silently re-admits a guaranteed-402 brand into buildAutoChain within one TTL window. Separately: xai-oauth.js treats HTTP 400 invalid_grant on refresh_token as permanent (unlike 429/5xx) via markRefreshDead/isRefreshDead persisted to ~/.acptoapi/xai-oauth.json, checked in auto-chain.js's xaiOauthLoggedIn() before hasCredentials().
